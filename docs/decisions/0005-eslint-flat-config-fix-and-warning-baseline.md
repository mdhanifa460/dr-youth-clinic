# 0005 — Fixed a broken ESLint flat config; `lint:check`'s max-warnings is a ratchet, not zero

**Status:** Active

**Context:** `eslint.config.mjs` used `{ extends: ["next/core-web-vitals", "next/typescript"] }` — `extends` is legacy `.eslintrc` syntax, not a valid flat-config key, so ESLint's flat-config schema silently ignored it. This meant `eslint-config-next` (and, inside it, all of `eslint-plugin-jsx-a11y`'s rules) was never actually active. `npm run lint:check` had been passing in CI this whole time because it was effectively linting against zero rules, not because the code was clean.

**Decision:** Fixed the config using `FlatCompat` (the documented way to resolve legacy shareable configs into real flat config). Turning real linting on for the first time surfaced ~1,600 pre-existing findings in one pass — overwhelmingly (~1,424) `@typescript-eslint/no-explicit-any`, which is this codebase's consistent, deliberate convention for typing Mongoose model calls (`(Model as any).find(...)`), not a bug. That rule is set to `"off"` rather than fixed or left as debt, because it isn't wrong here. A handful of genuinely-buggy findings were fixed outright (3 `jsx-a11y/alt-text` violations, 3 `react-hooks/rules-of-hooks` violations in `DoctorsSection.tsx` where hooks were called after an early return, 2 `no-unused-expressions` ternaries-for-side-effects). The remaining ~238 pre-existing warnings (`no-img-element`, `no-unescaped-entities`, `no-unused-vars`, `exhaustive-deps`) are real but low-severity debt, out of scope to bulk-fix as a side effect of unbreaking the config — `lint:check`'s `--max-warnings` is set to exactly that current count (238), not 0.

**Consequences:** `--max-warnings 238` is a ratchet: any *new* warning added by future work fails CI immediately (so debt can't silently grow), while the existing 238 don't block anything until someone deliberately cleans them up and lowers the number. If this number ever needs to go up, that's a signal worth noticing, not just bumping — treat an increase as something to ask about, not rubber-stamp.
